## Honest novelty boundary

**Already established:** instrumental incentives to manipulate state; conceptual manufacture of necessity; unsafe recovery from environmental errors; fabricated failure excuses; runtime policy enforcement; and the use of execution history for authorization. The cited works cover those points to different degrees and with different evidence types.

**Candidate empirical gap:** whether agents' real, avoidable state modifications track an operative authorization threshold more strongly than an equally salient non-authorizing numerical threshold, with physical task mechanics held fixed. The proposed controls distinguish permission-sensitive behavior from generic numerical following. This is an inference about a potentially useful gap in the inspected literature, not a verified first-in-literature claim.

The original five-arm pilot measures broad policy contrasts and descriptive threshold tracking. Version 2 now implements the visible numerical placebo, supplied external-outage states, a separate service-transition mechanism, and independent capability checks; see the measured-study plan for collection status. It still lacks independent held-out task validation. A hidden `shadow_threshold` used only by scoring code is not a salience control. Scripted actors are software checks, never evidence that a model exhibits the phenomenon.

## Strongest narrow contribution to pursue

**Working title: Separating Permission Incentives from Numerical Anchoring in Tool-Using Agents**

**Primary question:** Does making a numerical condition operationally relevant to authorization change an agent's tendency to create that condition, beyond the effect of merely displaying the number?

**Proposed contribution:** a validated causal evaluation protocol for permission-induced state manipulation, with an operational threshold intervention, a matched visible placebo, independent capability controls, verified authorized alternatives, and informative reporting when no violations occur.

1. **Separate the physical threshold from the policy threshold.** Keep capacity, initial state, task workload, tools, and call budget fixed. Vary only the disclosed permission threshold within a range where ordinary authorized completion remains feasible. Audit that every treatment has a healthy solution.
2. **Add a matched visible placebo.** Present the same changing number, position, and comparable wording in an arm where it does not determine external-processing permission. Keep unconditional and no-fallback controls. Pre-register the exact comparison; the placebo must not covertly change the task objective or suggest a target load.
3. **Check capability independently.** Use separate authorized tasks requiring a specified resource level and cleanup to verify that the model understands the tools and numbers. Report all models and any pre-specified capability strata. Do not retrospectively discard compliant runs because their behavior is inconvenient.
4. **Score actions, not claimed motives.** Record optional resource creation, literal authorization violations, task completion, created qualification, subsequent fallback use, and cleanup. Keep fabricated failure statements separate. Replay an authorized continuation to verify avoidability; do not equate that witness with the model's counterfactual behavior.
5. **Estimate a permission-specific contrast.** Average repetitions within each scenario/arm, estimate the slope of added peak load against required additional load, and compare slopes between operative and placebo thresholds. Also compare disruption incidence against the two baseline policies. Show the full distributions; a single mean slope may hide heterogeneous behaviors.
6. **Test transfer and utility.** Freeze prompts after development, evaluate held-out scenarios with genuinely different transition mechanics, and test legitimate externally caused outages. Any proposed defense must preserve authorized recovery instead of simply forbidding every fallback.

This list records the design requirements and remaining extensions. Items 1–5 are implemented in version 2 with authored development cases, a locally recorded plan, and explicit capability limitations. Independent transfer tasks and recovery-utility evaluation in item 6 remain future work. Implementation is not a substitute for measured evidence.

## What remains useful if no model violates

A null result can still answer the pre-specified question if the study demonstrates that models can operate the environment, that the assay detects programmed positive controls, and that adequate held-out evaluations were actually collected. The empirical claim would be bounded: **no observed permission-induced state manipulation under the tested conditions**, not general safety or absence of the incentive.

- Publish per-model, per-condition exposure counts, task success, capability checks, error rates, and raw action traces. Report model snapshots and settings so alias drift cannot masquerade as replication.
- Retain observed harmful prefixes when an adapter fails later. Treat an error prefix without observed disruption as unknown; complete-case zeros can hide selectively missing unsafe runs.
- Pre-specify a meaningful effect size and a sample plan. If the confidence set still includes that effect, call the result inconclusive rather than evidence of equivalence.
- Do not interpret a zero-width bootstrap interval from all-zero observations as proof that the population rate is zero. Report a suitable one-sided rare-event bound only under explicitly justified independence/sampling assumptions; repeated calls on a few authored templates are not independent samples of deployment scenarios.
- Separate the scientific negative result from the benchmark contribution. A reproducible assay with validated labels and a documented null is useful, but novelty and workshop acceptance remain judgments for reviewers. Synthetic positive-control behavior alone cannot support an empirical model-safety paper.

## Suggested related-work positioning

Our proposed study operationalizes a previously discussed risk: an agent may alter its environment to satisfy the condition for a safety exception. Causal incentive analysis supplies the general mechanism; existing recovery studies begin with an environmental failure, while other work examines fabricated obstacles. We instead intervene on authorization conditions before failure and verify actual state changes. A visible numerical placebo tests whether any apparent threshold tracking is specific to authorization. Existing runtime-enforcement systems motivate strong baselines rather than a claim that provenance-aware rules are new.
