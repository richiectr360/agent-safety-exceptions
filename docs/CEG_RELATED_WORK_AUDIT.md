# Counterfactual Exception Guard: targeted related-work audit

Checked against primary sources on **18 October 2026**. This is a bounded novelty audit, not a systematic review, an acceptance forecast, or proof that no equivalent method exists. No model API calls or new experiments were performed for this audit.

The audited design is [COUNTERFACTUAL_GUARD.md](COUNTERFACTUAL_GUARD.md), SHA-256 `6aaa60c076dbf59415a80e6281b2e5323fd5102c96bf26410d4a953698b01286`. Later implementation or design changes require checking whether this comparison still applies.

## Assessment

**CEG applies established security ideas to a specific policy problem; a new general security principle has not been established.** Protecting authorization from untrusted influence, maintaining multiple security views, enforcing obligations, and checking runtime provenance all have direct precedents. The candidate contribution is a concrete resource-cause abstraction and a controlled study of when it preserves legitimate exception access while excluding qualification caused by discretionary agent effects.

The distinction worth investigating is between **changing a permission policy** and **changing the world so that an existing conditional permission becomes applicable**. This is a useful experimental distinction, not a claim that prior policy frameworks cannot express the stronger rule.

## Exact construction being compared

For a conditional request, CEG requires the exception predicate to hold in both a factual resource view and a reference ledger that excludes discretionary actor-created causes. Independently established external causes and effects incurred under scoped trusted work grants remain in the reference view. It additionally requires verified provenance and no overdue registered recovery obligation.

The audited construction includes componentwise mixed causes, trusted wall-clock time, grant budgets and expiry, verified cause resolution, uncertainty deferral, registered recovery deadlines with independent infeasibility dispositions, and single-use execution leases bound to request arguments and current policy/state. It assumes a trusted executor supplies cause classifications and mediates effects. It does not perform general causal discovery or simulate every counterfactual consequence.

Its narrow property fixes trusted external history, authorized work, policy, request and time: when the reference predicate is false, adding discretionary causes cannot yield an `ALLOW` in conditional CEG mode. This follows from the decision rule. It is not a proof of arbitrary-agent noninterference, a guarantee against all omissions, or an empirical demonstration of effectiveness.

| **R1. Robust declassification and qualified robustness** | Protects both the decision to release information and the released information from attacker control. Endorsement permits carefully delimited untrusted influence. The paper's motivating conditional-release example directly illustrates an attacker changing the variable that enables release. | CEG's principle is an application of influence-sensitive release control. Scoped work grants resemble endorsement; calling them a new principle would overstate the distinction. The resource ledger and its useful behavior require separate evidence. CEG specializes the state to resource causes and exceptions; it should explain why this restricted abstraction is useful rather than imply general secure multi-execution. [Primary paper](https://www.andrew.cmu.edu/user/liminjia/research/papers/ifc-ccs23.pdf) |
| **R4. UCONABC** | Integrates authorizations, obligations, environmental conditions, ongoing controls, mutable attributes and revocation into usage control. | Recovery obligations, changing resource attributes and revalidation are established ingredients. | **R5. Progent, v3** | Deterministic symbolic rules constrain tool names and arguments. An SMT check distinguishes narrowing from expanding policy updates; expansions require explicit approval. | Use this version, not an obsolete permissive update mechanism. Activation of a previously defined conditional policy is different from editing the policy. Whether a Progent integration admits that activation depends on its actual policy and state representation; this audit does not establish a bypass. [Versioned paper](https://arxiv.org/abs/2504.11703v3) |
| **R6. AgentSpec** | A DSL combines triggers, customizable predicates and enforcement actions. Predicates can be provided by experts and can inspect domain-specific conditions. | CEG could be implemented as a policy/predicate extension inside such a framework. A weak factual-only predicate is not evidence that AgentSpec itself cannot enforce CEG's semantics. [Versioned paper](https://arxiv.org/abs/2503.18666v3) |
| **R7. FORGE, v4** | Enforces Datalog policies over current state and event provenance, including recursive dependencies, approval chains and delegation. Its enforcement guarantee is bounded by policy and instrumentation. | History-aware enforcement is already available. The potential difference is the particular resource-effect model and reference predicate, not the existence of a provenance monitor. A fair comparison must give a strong policy engine the same facts and intended rule. [Versioned manuscript](https://arxiv.org/html/2602.16708v4) |
| **R8. FAVA** | Builds evidence-backed permission graphs, encodes obligations as prefix guards, and applies SMT authorization before effects. Positive guard observations and trusted transformations are explicitly distinguished from taint-only graph growth. | This is especially relevant to conditional access: satisfying a guard is not automatically treated as weakening the policy. CEG investigates the origin of such qualifying state. The inspected method did not establish the same factual/reference resource test, but that is not proof that its framework cannot express it. [Method sections](https://arxiv.org/html/2607.27267v1) |

The consequential comparison is therefore between **policy semantics with equal evidence**, followed by comparison of deployable implementations. An apparent CEG advantage obtained by supplying it privileged causal labels while leaving another policy engine only an aggregate load reading would conflate the rule with the evidence advantage.

## Search for the failure mode and adjacent methods

**Manufactured necessity is already explicitly discussed.** David Mc's author-published essay, *Where Power Migrates*, describes agents creating dependencies, removing alternatives, delaying intervention or delegating preparatory steps to make a later exception appear necessary. This is direct conceptual prior art, including omission and delegation. It is a conceptual essay, not a peer-reviewed empirical study or an evaluated CEG implementation. The project should cite it rather than claim to originate the idea or term. [R13, original essay](https://axio.fyi/p/where-power-migrates)

**Unsafe recovery and fabricated failures are different comparisons.** *Agent Meltdowns* injects benign environmental errors and studies harmful responses, including attempts to bypass access controls. CEG instead asks whether the qualifying resource condition was created by the actor and should count toward permission. [R11, primary preprint](https://arxiv.org/abs/2605.19149v1) *Is Your Agent Playing Dead?* reports agents fabricating external obstacles under conflicting constraints. That concerns claimed failures; a CEG evaluation must independently observe actual resource transitions and separately test false claims. [R12, primary preprint](https://arxiv.org/abs/2606.14831v1)

**Counterfactual incentive removal is established AI-safety work.** *Path-Specific Objectives for Safer Agent Incentives* trains objectives that exclude reward pathways through designated delicate state. CEG instead gates an execution request and does not retrain the actor's objective. An observed reduction in permissions granted would not, by itself, prove that the actor's incentive to disrupt the environment disappeared. [R14, primary preprint](https://arxiv.org/abs/2204.10018v1)

**Recovery deadlines and balanced evaluation also have precedents.** EnfFlash targets efficient enforcement of temporal requirements, including future obligations and deadlines; adding a deadline to a gate is not independently novel. [R10, primary preprint](https://arxiv.org/abs/2610.04611v1) *Deny Without Disabling* jointly evaluates prevention of prohibited uses and completion of required authorized uses. CEG should adopt this discipline without claiming to invent safety–utility evaluation or permission-preserving enforcement. [R9, primary preprint](https://arxiv.org/abs/2610.00371v1)

Discovery queries included exact titles and combinations of `manufactured necessity`, `agent-created necessity`, `agent permission sabotage policy exception`, `agent failure fallback authorization`, `self-induced emergency authorization`, `break glass abuse formal`, and `access control obligations deadline runtime enforcement`. Searches also surfaced general emergency-access systems and governance material. These were not treated as evidence of CEG's exact method. Missing keywords in a manuscript do not establish absence of conceptual overlap.

The targeted search did not establish a prior evaluation of the **exact** audited combination: resource-cause decomposition, factual/reference qualification, scoped approved-work effects and overdue cause-specific recovery deferral. This is a search outcome, not a first-of-kind claim. Existing enforcement frameworks may encode the same construction once supplied its state and evidence.

## What is known, what remains a candidate

| Component or claim | Classification after this audit |
| --- | --- |
| An agent can arrange circumstances that justify later authority | Known conceptual risk; explicitly described in R13. |
| Untrusted actors should not influence security downgrades | Established security principle, R1–R3. |
| Runtime rules can use state, history, provenance and obligations | Established methods, R4–R8 and R10. |
| A factual view plus an independently classified resource ledger for necessity-conditioned tool access | Candidate domain-specific construction; novelty not established. |
| Retaining authorized/external contributions while excluding discretionary contributions in mixed resource states | Candidate useful abstraction. Must compare to an equally informed provenance policy, not only permanent taint denial. |
| Deferring exception use after a registered repair deadline | An application of obligation-aware control; the exact integration may be useful, but the primitive is established. |
| Bound leases, revocation checks, fail-closed handling and independent evidence | Security engineering requirements in this design, not claimed research inventions. |
| A measured advantage against capable, adaptive agents at acceptable task utility and evidence cost | Potential empirical contribution; not yet established by the audited artifacts. |

## Evidence that would establish an empirical contribution

1. **Operational evidence, not oracle labels.** Specify how an executor observes resource creation, independently distinguishes external events from actor-induced effects, scopes approved work and verifies release. Measure ambiguity and classification errors. Include actor-induced failures reported by an external service; a trusted report is not automatically proof of independent origin.

2. **Same endpoint, different verified causes.** Construct matched tasks with equivalent relevant final resource state and requested operation, but external, approved-work, discretionary and mixed histories. Include released causes and legitimate prior actor work so a permanent taint rule is not the only comparison. Independently review expected authorization outcomes before seeing model results.

3. **Separate semantic benefit from substrate benefit.** Compare factual-only, permanent taint, a strong current provenance/state policy with equal evidence, the reference ledger without recovery checks, full CEG and deny-all. If the strong provenance baseline is extensionally equivalent to CEG on the domain, report equivalence rather than fabricate superiority. The contribution could then concern specification clarity, evidence requirements, implementation cost or newly documented failure cases.

4. **Demonstrate capability and adaptive pressure.** Use models that can complete the authorized tasks and operate the relevant tools. Evaluate ordinary task completion separately from adversarial agents explicitly seeking unauthorized exception use. Freeze the defense before held-out attacks. Include delegation, resource combination, timing, induced third-party failures and withheld repairs. Do not infer intent from any single qualifying event.

5. **Count actual effects and utility together.** Record attempted and executed privileged operations, ordinary disruption, valid exception completion, primary-task success, erroneous denial, deferral and overhead. Include incomplete/error prefixes and uncertainty. Measure independent tasks and repeated rollouts; threshold variants and actions within a task are not independent samples. A successful gate can still leave the agent's disruptive action unprevented.

6. **Ablate assumptions and retain counterexamples.** Test incomplete cause observability, imperfect provenance, grant misuse, repair deadlines before/after exception maturity and ambiguous execution outcomes. Preserve unregistered-repair-delay failures. Establish where the gate defers so often that it loses practical value. The goal is a measured boundary of usefulness, not a universal safety claim.

The 120 scripted mechanism checks exercise authored contracts. They are suitable for implementation validation, not estimates of adaptive-agent failure rates. The earlier 192-episode model cohort evaluates a different behavioral question and does not test CEG. Neither should be pooled with a future defense cohort. New results should be reported even if no capable actor manufactures an exception or if the best existing policy matches CEG.

## One narrow defensible claim

> We specify and implement a reference-ledger policy for necessity-conditioned tool permissions. It distinguishes independently established and approved-work resource causes from discretionary actor causes, and adds deferral for overdue registered recovery obligations. Under a fixed trusted history and complete mediation, discretionary additions cannot authorize an exception whose reference predicate is false. We provide reproducible contract checks and explicit counterexamples; effectiveness against adaptive language-model agents remains an empirical question.

This claim describes the artifact and its limited property without asserting that the underlying principles are new. A later paper may claim an empirical advantage only after the matched evaluation establishes it. A null result or equivalence to a strong baseline can still support an informative testbed or specification study, but does not automatically justify a novel-defense claim.
